===========================================================
 ROBOT DIAN - corrige el redondeo del XML y recalcula el CUFE
===========================================================

Para que sirve
--------------
Tu software genera el XML con centavos descuadrados y la DIAN lo rechaza.
Mientras el proveedor arregla el software, este robot toma el XML, corrige
los valores y le pone el CUFE nuevo. Asi no hay que esperarlos.

Que revisa y corrige
--------------------
  - Por cada linea:  LineExtensionAmount = cantidad x precio (2 decimales),
    aplicando descuentos y cargos de la linea.
  - Por cada impuesto:  TaxAmount = base x tarifa (2 decimales).
  - Que la base gravable del documento sea la suma de las bases de las lineas.
  - Los totales:  LineExtensionAmount, TaxInclusiveAmount y PayableAmount
    del bloque LegalMonetaryTotal.
  - Recalcula el CUFE (SHA-384) con los valores ya corregidos y lo reemplaza.

Ademas AVISA (sin tocar nada) si la fecha de vencimiento quedo antes que la
de emision, o si el ambiente del config.ini no coincide con el del XML. Los
avisos salen en el informe con la palabra OJO. Si ves un OJO, revisa antes
de firmar.

Sirve para Factura, Nota Credito y Nota Debito.


-----------------------------------------------------------
 DOS VERSIONES - ELIGE UNA
-----------------------------------------------------------
Hacen exactamente lo mismo. Comprobado: sobre la misma factura las dos
sacan los mismos descuadres y el mismo CUFE, caracter por caracter.

  A) PowerShell  ->  NO HAY QUE INSTALAR NADA.
     PowerShell ya viene con Windows. Usa estos:
         CORREGIR_ARRASTRANDO.bat
         VIGILAR_CARPETA.bat
     Esta es la recomendada.

  B) Python  ->  hay que instalar Python una vez. Usa estos:
         python_CORREGIR_ARRASTRANDO.bat
         python_VIGILAR_CARPETA.bat
     Solo si prefieres Python por algo. Si no, ignora estos dos.


-----------------------------------------------------------
 PREPARACION (una sola vez)
-----------------------------------------------------------
Abre  config.ini  con el Bloc de notas y pon:

      clave_tecnica = (la clave tecnica de tu software, del portal DIAN)
      ambiente      = 1 si es produccion, 2 si es habilitacion

Guarda y cierra. Eso es todo.

El ambiente en realidad lo lee del propio XML, del campo ProfileExecutionID,
porque ese es el que valida la DIAN. El de config.ini es solo respaldo para
cuando el XML no lo traiga. Si los dos no coinciden te avisa en el informe.
Esto importa porque el ambiente entra dentro del CUFE: si se calcula con el
ambiente equivocado la DIAN no te dice "ambiente", te dice "CUFE incorrecto".

Sin la clave tecnica el robot igual corrige los valores, pero NO puede
calcular el CUFE, porque la clave entra dentro del hash. Te lo avisa.

Solo si eliges la version B: instala Python desde
https://www.python.org/downloads/ y en la PRIMERA pantalla del instalador
marca la casilla "Add Python to PATH".


-----------------------------------------------------------
 USO - FORMA 1: arrastrar
-----------------------------------------------------------
Arrastra uno o varios XML (o una carpeta entera) encima de

      CORREGIR_ARRASTRANDO.bat

Al lado de cada XML quedan dos archivos:
      FACTURA_corregido.xml   <- el que pasas a tu .bat de firma y envio
      FACTURA_informe.txt     <- que estaba mal y en cuanto


-----------------------------------------------------------
 USO - FORMA 2: carpeta vigilada (desatendido)
-----------------------------------------------------------
Haz doble clic en

      VIGILAR_CARPETA.bat

y deja la ventana abierta. Todo XML que aparezca en la carpeta "entrada"
se corrige solo y sale en la carpeta "salida". El original se guarda en
"procesados" (o en "errores" si el archivo estaba dañado).

Si quieres que vigile directamente la carpeta donde tu software deja los
XML, en config.ini cambia:

      entrada = C:\ruta\donde\tu\software\deja\los\xml

Todo queda registrado en  registro.csv  (se abre con Excel): fecha,
archivo, cuantos descuadres tenia, CUFE anterior y CUFE nuevo.


-----------------------------------------------------------
 DONDE ENCAJA EN TU PROCESO
-----------------------------------------------------------
Tu proceso queda asi:

   1. Tu software genera el XML
   2. EL ROBOT lo corrige y le pone el CUFE nuevo
   3. Tu .bat de siempre: firma, arma el .zip y lo envia a la DIAN

El robot va en el paso 2, entre los dos. No cambia nada de lo que ya tienes:
no firma, no arma zip y no envia. Solo deja el XML bien.

El orden NO se puede cambiar. Si se corrige un XML que ya esta firmado, la
firma deja de validar, porque la firma corresponde a los valores viejos. Por
eso el robot tiene que trabajar sobre el XML SIN firmar, antes de tu .bat.
Si le pasas uno ya firmado el robot igual lo corrige, pero te lo avisa en el
informe con letras grandes para que no lo mandes asi.

Si tu .bat espera un nombre de archivo exacto: en modo vigilar deja
nombre_salida = igual en config.ini (asi viene). El XML corregido sale en la
carpeta salida con el mismo nombre que tenia el original, entonces tu .bat lo
encuentra sin cambiarle una sola linea. Si prefieres distinguirlos, pon
nombre_salida = sufijo y saldra como NOMBRE_corregido.xml.

Ojo: en config.ini la carpeta salida NO puede ser la misma que entrada. Si las
pones iguales el robot se encontraria su propio archivo corregido una y otra
vez, por eso en ese caso no arranca y te lo dice.
